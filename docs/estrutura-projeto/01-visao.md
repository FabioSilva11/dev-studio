# Visão do Produto

## Nome

Dev Studio

## Proposta

Criar um editor visual mobile-first, inspirado na experiência do Sketchware, para construir aplicativos a partir de telas, widgets, propriedades e lógica visual.

O projeto deve ser feito em Flutter, mas não deve tentar ser um clone interno do Sketchware. A inspiração é a experiência de uso: criar apps visualmente pelo celular. A arquitetura deve ser própria.

## Pilares do Produto

1. Editor visual de telas.
2. Schema próprio de projeto.
3. Programação visual por blocos.

A programação visual é parte central da proposta. Ela permite criar comportamento usando elementos gráficos conectáveis, em vez de escrever código diretamente.

## Público Inicial

- Pessoas que querem criar apps simples pelo celular.
- Estudantes e iniciantes em programação mobile.
- Criadores que gostam da ideia do Sketchware, mas querem uma base moderna.
- Desenvolvedores que desejam prototipar telas e fluxos rapidamente.

## Princípios

1. O modelo interno do Dev Studio é a fonte da verdade.
2. Projetos devem ser salvos em formato próprio e documentado.
3. Compatibilidade com Sketchware é importação, não dependência.
4. O editor visual vem antes do gerador de APK.
5. Poucos widgets bem feitos valem mais do que muitos widgets frágeis.
6. Toda nova capacidade precisa respeitar salvamento, reabertura e testes.
7. A programação visual deve ser modelada desde o início, mesmo que a implementação completa venha depois.

## Resultado Esperado

No primeiro estágio, o Dev Studio deve permitir criar uma tela visual simples, salvar o projeto e reabrir sem perda de informação.

O schema inicial deve reservar espaço para eventos e blocos, para que a programação visual seja adicionada sem remendos estruturais.

No futuro, o projeto pode evoluir para geração de código Flutter, geração Android, sistema completo de blocos e importação parcial de projetos Sketchware.
